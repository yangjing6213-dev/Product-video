# Workflow

Follow all stages in order. Codex owns creative decisions and artifacts. The CLI owns deterministic validation, state, cache/resume, tool invocation, and actual JSON evidence.

For current new jobs, [GENERATOR-QUALITY.md](../../../docs/guides/GENERATOR-QUALITY.md) is the active route: `init → authored input/spec/copy approval → voice or measured audio reuse → compose → run --quality draft --resume --supplied-only → concentrated human review → explicit high render → release-check`. Legacy direct synthesis and flattened author-page examples are historical replay material, not defaults. Preserve the complete five-item secondary contact block and use the ENHE website as the primary CTA. `run` now invokes the same common composition for current jobs and defaults to a draft; it does not approve M2 or final delivery.

1. **Read rules and input** — Read `AGENTS.md`, this Skill, input JSON, available assets, schemas, and `npm run video -- help`. The CLI uses positional `help`; `--help` is not implemented. Do not assume a command exists from documentation alone. Read the project brand catalog and the current quality task's milestone/acceptance record before choosing assets or defaults.
2. **Preflight** — Select individually approved catalog versions by product meaning and add `brandLibrary` to every new input. Run `npm run video -- init --input <product-input.json>` and `npm run video -- verify-input --project <projectId>`. Confirm schema, URLs/paths, required assets, licenses, target directory, and local tool availability. Inspect `frozen-brand-assets.json` and its exact copied hashes before preview. Preserve report JSON and nonzero failures.
3. **Capture & Understand** — Run `npm run video -- capture --project <projectId>`. The default path invokes HyperFrames `capture` and has automatic fallback to `supplied-assets` when capture fails. Pass `--supplied-only` to skip URL capture and require usable licensed supplied visuals. Write `PRODUCT-SUMMARY.md` with claims mapped to evidence.
4. **DESIGN.md gate** — Before composition HTML, write the style prompt, colors with roles, designed display font and clear body/subtitle fonts, original Logo rules, motion tone, safe areas, and what to avoid. Verify actual fonts and their licenses. Base decisions on real brand evidence. In R2, prepare two visual directions and the M1 motion/voice candidates for user review; do not treat a model's choice as user acceptance.
5. **SCRIPT.md** — Organize each product's story independently from its evidence. The existing MVP contract supports a result-first 30–60 second script with one problem, up to three evidenced benefits, and one CTA; R2 samples and approved deliverables use their stated durations. Keep screen copy shorter than narration. For an intentionally silent task with `narrationMode=none`, mark narration as `NONE` and design readable screen copy; this cannot fulfill required R2 narration. **Copy confirmation is required before generating speech or video:** present narration, screen text including the author ending, matching subtitles, and CTA; freeze `copy-script.json`, then record the real user instruction and exact reviewed hash with `copy-review`. Follow [COPY-REVIEW.md](../../../docs/guides/COPY-REVIEW.md). A user choosing motion or a voice does not approve the text. Changed words require a new reviewed variant; changes only to approved visual or vocal expression keep the wording approval.
6. **STORYBOARD.md + video-spec.json** — Record versioned recipes, selected asset IDs, hero frames, crop/camera intent, finite entrance motion, transitions, caption regions, and fallbacks. Existing MVP specifications require 5–8 single-purpose scenes; do not force this whole-film count onto the separate 8–12 second M1 sample. Explain why each shot advances this product's story. Build the author ending from the complete five-item editable contact text and graphic layers. Do not add a portrait or full CV unless the current user explicitly authorizes it. Validate the applicable JSON contract before composition work.
7. **Voice, transcript, and timing** — Use HyperFrames TTS only when the current voice list supports the locale and its use is authorized. Otherwise use authorized audio; an optional silent task may use `narrationMode=none`. Required R2 narration remains pending if a suitable voice is unavailable. Reuse accepted audio before generating alternatives, and obtain authorization before cost or external upload. With audio, generate one real transcript source and update actual scene timing from it; do not maintain competing caption text. For a current local Chinese job, read the current entry in `docs/guides/CHINESE-TTS.md`, declare the explicit voice profile and pronunciation map, then run `npm run video -- voice --project <id>`. Kokoro phrase/句级 PCM boundaries are not ASR 逐词 timestamps. Qwen uses retained real Whisper DTW anchors; its `--prepare-only` step permits measured timing adjustments only in a new unfrozen draft before normal `voice` consumes the prepared audio without repeat inference. Bind the audio and 字幕/transcript artifacts with SHA-256 evidence across `voice-report.json` and `narration-artifact-check.json` (or equivalent actual reports), including an SRT text/time comparison against the measured cues. Keep `ASR` as `NOT_RUN` when no real transcription backend ran. The guide's historical direct synthesis commands only replay old benchmarks. A playable candidate or installed backend does not prove the requested young adult male voice was accepted; the selected B sample does not approve new-text audio or verify cross-text identity.
8. **Build HyperFrames compositions** — For current jobs, author `Scene.action` using real subject assets/layers and run `npm run video -- compose --project <projectId>`. The same compiler is invoked by normal `run`; do not create a private per-product renderer. Establish static layout first, then deterministic finite subject action. Use the frozen brand paths and retained licensed music. Retain HyperFrames; review source and license before adapting external methods. A rendering limitation must be evidenced before any separately authorized renderer change.
9. **Lint, validate, and inspect** — Run `npm run video -- qa --project <projectId>` and retain the actual JSON result. Fix every error. Explain or repair each warning; never bulk-ignore it.
10. **Draft render** — Run `npm run video -- render --project <projectId> --quality draft`. Record the actual render report and preview URL only when observed.
11. **QA repair** — Inspect contact-sheet frames and machine reports. Fix the smallest evidenced defect, rerun the failed check, and stop after bounded retries. For renderer failures, use the available HyperFrames doctor/info diagnostics before changing code.
12. **Final render** — Run `npm run video -- render --project <projectId> --quality high --resume` only after input, asset, structure, visual, and audio gates pass. An unknown-license asset blocks this stage. For R2, do not start M2 production before explicit user acceptance of the M1 visual, motion, and voice artifacts; a diagnostic/sample render is not final acceptance.
13. **Media probe, scorecard, and report** — Verify decode, dimensions, fps, duration, required streams, black frames, and silence rules. Complete an independent visual scorecard and record reviewer type plus whether human review occurred; never label a Codex review as human. Preserve `qa-report.json`, `scorecard.json`, `render-high-report.json`, `render-report.json`, and `run-report.json` with real commands, exits, timings, paths, and remaining risks. Per-command details are stored under `reports/commands/`. The current benchmark videos are local-only deliverables and still require explicit human review before external publication.

## Resume and cache

`verify-input`, `capture`, `qa`, `render`, and `run` all use `--resume` for stage reuse. Identical-input `init` is idempotent without it. A stage is reused only when its fingerprint matches and every registered output still exists with unchanged bytes; if an output is missing or its bytes change, that stage reruns. After the creative artifacts, copy approval, and required voice input exist, `npm run video -- run --project <projectId> --resume` resumes the post-authoring deterministic chain. It does not author or approve those inputs. Trust the reported input hashes and stage states, and use `reports/run-history.json` for the preserved first playable draft timestamp. Never call Codex recursively from `run`.

Frozen brand bytes have a stricter boundary: if a snapshot or frozen file is missing, altered, or inconsistent, stop for a concrete repair rather than reselecting from a newer catalog. Keep the same selected versions, authored plan, timing, and approved audio on retry. A library update affects future selections only. Record deliberate creative changes as a new variant; keep the original job and videos intact.

If the current CLI rejects a documented option, capture the actual help/error, use the supported equivalent, and report the difference. Never edit a JSON report to simulate success.

## Failure routing

| Failure | Response |
|---|---|
| URL capture fails | Switch to `supplied-assets`; record final URL/error and missing coverage. |
| Target-language TTS is unavailable | Reuse suitable authorized audio; optional silent tasks may use `narrationMode=none`. Required narration remains outstanding. |
| Complex transition is unsupported | Diagnose the limitation and try a bounded local repair or a suitable supported transition. Do not call a rejected visual fallback accepted. |
| Screenshot resolution is insufficient | Use a native-resolution crop plus brand card; do not enlarge beyond 2x. |
| Caption overflows | Shorten copy, adjust the container, or fit text while preserving the two-line limit. |
| Render fails | Run available doctor/info diagnostics, make a minimal repair, and retry a bounded number of times. |
| Asset license is unknown | Keep it out of final and request/reselect authorized material. |
| Library or frozen asset mismatch | Preserve all bytes, report the exact failed hash/path, and require an explicit corrected variant or byte-identical restoration. |
| M1 visual or voice approval is absent | Finish authorized engineering and review artifacts, report the unapproved gates accurately, and do not enter M2/batch production. |

For migration and full private backup, use [the IP library guide](../../../docs/guides/IP-LIBRARY.md). Migration takes an explicit source path; no daily pipeline scan or external fallback is allowed. Source deletion is a separate, proof-gated operation within the exact source authorization. Do not interpret a missing source folder without a valid receipt as a successful move.
