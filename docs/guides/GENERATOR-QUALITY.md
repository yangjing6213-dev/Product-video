# 当前产品视频生成流程

## 新任务封面与作者片尾

以 [AUTHOR-FRAMING.md](AUTHOR-FRAMING.md) 为准：固定已审核的深色实景玻璃面板风格；每个新任务询问人物，未提供使用现有授权默认人物，提供则封面/片尾使用同一新人。每支新视频选择不同真实场景，原任务恢复冻结不变。人物替换不改变配音、姓名或联系方式。此规则优先于下方历史“默认不加头像”或固定海报示例；私有默认素材缺失时必须明确报告。


活动规则的唯一机器来源是 `recipes/policies/generator-quality.v3.json`。本指南适用于新任务；v1/v2 规则保留原字节，可信历史冻结任务可本地重放，通过旧计划恢复不等于通过新质量验收。

## 内容与片尾

- 面向普通 AI 用户：先展示一个真实问题和结果，再说明用途与使用前提。标清正在推广的产品、演示项目与恩禾品牌的关系。不能把 Codex Skill 说成免配置网页产品。
- 产品来源 URL 用于证据。主要 CTA 是恩禾官网 `www.enhe-tech.com.cn`。完整口播使用用户批准的“需要更多 AI 工具，进入恩禾官网搜索，让每一个普通人，都能轻松驾驭AI，把想法变成现实，把效率变成价值。”，不得截短为仅提及官网。后半句是愿景表达，工程测试不证明效果保证；没有核实的站内产品页、购买入口或完整教程不能承诺存在。
- 用户明确要求**完整保留作者联系方式**。`init` 从私有 `assets/brand/enhe/author/contact-profile.json` 导入并冻结 `authorContacts`；GitHub、X / Twitter、网站、微信、邮箱五项必须齐全。调用方不能用不完整信息覆盖已授权 profile。无 profile 时先补齐已授权信息，不能凭空生成。
- 官网为主要行动入口，联系方式在片尾独立分层展示。字号、层级、空白与停留时间按实际阅读量设计，五项联系块至少六秒，不自动恢复整段履历或作者头像。联系内容纳入 `copy-script.json`，更改需明确文字范围批准。
- 不使用 IP 角色；保留原 Logo。真实成果、界面、文章、摄影素材分别保留来源和授权。字幕无底色、底板、渐变或盒阴影，允许轻微文字阴影。
- 共用标题均衡换行，避免末行落单字；联系块共享标签列和内容列，并按文字基线对齐。竖版所有镜头都为两行字幕留出空间，片尾按联系文字的自然高度分配图片区。前后对照按声明的 before/after 顺序绘制，避免原图盖住结果。仍需检查实际 MP4；DOM 字号检查不等于识别并检查截图内部文字。

## 正常入口

1. `npm run video -- init --input <brief.json>`：继承普通用户、官网、透明字幕、完整次级联系方式的活动默认。核验品牌冻结和素材；使用 `verify-input`、`capture --supplied-only`。生成旁白资源尚未存在时，先按后续 voice 步骤产出再做完整 preflight。
2. Codex 基于证据编写 `DESIGN.md`、`SCRIPT.md`、`STORYBOARD.md`、`video-spec.json`。完整展示旁白、屏幕文字（包括联系人）、字幕和 CTA，使用 `video:quality copy-freeze/copy-review` 记录用户真实文字与精确稿件哈希；不能伪造批准。每个 scene 声明 `action`，用真实 assetId、原始/目标状态、动作原语、帧区间和阅读停顿驱动共用合成。真实分层必须声明子素材和准确像素边界；用两个文字标签代替真正图层不能通过。
3. 本地新中文旁白使用 `npm run video -- voice --project <id>`：输入声明 `audio.voiceProfile`、`audio.deliveryMode`（`natural` 或 `presenter`）、读音表，以及 `external-audio` 的 `assets/narration.wav`；每个有声 scene 声明 `voiceDirection`。显式 profile 选择既有 Kokoro 或本机 Qwen 参考声音分支，缺失配置或变更证据会阻止复用，不自动换供应商。当前已选声音的相同批准口播复用原字节；新批准口播使用已授权 Base 与真实 Whisper DTW。先按 [中文旁白指南](CHINESE-TTS.md) 通过 `--prepare-only` 保留实测音频和 cues，调整新未冻结草稿的时间，再运行正常 `voice` 复用准备包。不能改批准文字、旧冻结稿或反复加速/重推理。需要追加安装、费用或外部上传时按现有授权范围集中确认。
4. 使用 `npm run video -- compose --project <id>` 生成共用 HyperFrames 合成；`npm run video -- run --project <id> --resume --supplied-only` 也会在已核验音频后调用同一合成并默认只出 draft。完整旁白字幕、真人声线和素材均由实际文件绑定。原项目已有不同产物时建立新 variant，不删除旧片或覆盖旧冻结稿。
5. 检查 `qa`、真实浏览器画面、动作前中后与反向 seek、HyperFrames lint/validate/inspect、MP4 全解码、音轨和时长。`render --quality high` 要求当前计划的真实人工视觉和声音批准。技术静音样片允许 draft，但不能取得声音或最终验收。
6. `npm run video -- release-check --project <id>` 只生成本地质量就绪报告，分别检查工程、视觉、声音、受众与最终接受；缺少检查不能 PASS。该命令不发布。所有 Commit、Push、部署和公开发布仍遵循当前任务明确授权。

## 冻结、声音与泛化

只有画面变更、且声音全文与时间线不变的新 variant，可显式运行 `node src/cli.ts voice --project TARGET --reuse-from SOURCE`。两端完整文案都需已有批准；正常管线按独立绑定验证原始录音、原始生成上下文、快照与目标，收据不改写。不支持链式复用，原项目必须保留在完整本地备份中。新文字仍走现有本地合成与真实对齐，不因复用功能自动变更声线。

完整规则哈希、输入、文案、读音、声线参数、模型身份、真实资源、字体、时间线和合成入口进入任务快照。恢复不重新选 IP、不自动换声音、不采用新素材版本。旧批准不能替新结果签字。

音频实测驱动时长；字幕层不决定合成切分。保留模型真实语义段或音素边界证据，未运行 ASR 就标 `NOT_RUN`。响度/峰值、程序字段和模型打分不能代替普通话、年轻感、热情、自然表达的真人试听。

从私有 `.tools/selected-voice.json` 读取用户当前选择；已选声音的音频、副本、批准回执及哈希按版本保留，任务 profile 冻结精确引用，不重新试音或恢复被否定的 `zm_031`。当前 voiceId 以已验证的选择文件和回执为准，不硬编码历史 B 的标识；VoiceDesign 的描述与固定 seed 不证明新文本身份一致。Base 参考合成记录 `crossTextVoiceIdentity: NOT_VERIFIED`，样本批准不代表新稿听审。仍需对两类不同内容（包含未参与调参稿）通过正常入口验证，并分别完成真实听审，才能声称通用质量改善。尚无选择的任务才按其明确授权制作候选，不能借本段重启已有选择。

`voiceDirection` 必含 purpose、attitude、emphasis、pace、pause、visualEvent。emphasis 必须是对应旁白的真实子串；它表达导演意图，不表示模型原生支持逐词重音。当前 Kokoro 实际接口只有语速和句/分句停顿；不支持情绪指令、pitch、energy 或逐词 emphasis。映射版本为 `kokoro-zh-direction-v1`，有效 speed/sentencePauseSec/clausePauseSec、模式和有序逐段方向进入缓存身份、音频证据与 QA。导演备注不得进入朗读正文。字幕从真实音素/语义段时序拆分，不作为 TTS 合成单位；超时按实测调整画面，不做强制变调/加速。

Qwen Base 使用 `qwen3-reference-v1`：上述方向与模式仅为导演元数据，不应用原生 `instruct` 或逐场景韵律控制，不套用 Kokoro 的速度/停顿参数。字幕来自真实 `whisper-cpp-dtw-anchors-v1`，音频、词锚点、原始识别、执行参数、模型、批准文案、选择回执及冻结运行文件必须一致；不得将书写正规化或已记录的问句语气词省略报告成逐字相同。完整证据与限制见中文旁白指南。

新展示默认 `brand.presentation: "workflow"`，用三类 `Scene.workflow` 搭配 `workflow-progress`。`vertical-3` 是文章、判断、画面方案逐层提炼；`horizontal-3` 用不同真实预览表现内容、分层、成果；`feature-row-4` 含四项功能的标题、真实预览和具体字段。每个字段必须进入已审 `onScreenText`，卡面应为精致浅色，背景照片仅承担氛围。普通、当前、完成状态结合内容强调、亮度、阴影与连线推进；editorial-v2 保持卡片位置稳定，用预览内容的连续揭示取代旧版抬升，不使用占位横线或单纯黄框。真实摄影、原始 Logo、排版文档与实际合成成果保留来源；不引入手绘图、卡通/IP，也不将照片参考宣称为产品输出。

M1 用两类代表画面、含主体动作与语音的 8–12 秒样片和最多三份试听集中确认。A/B/C 是两款产品的回归组，另外锁定一个未参与调参的真实产品作为保留样本；不能渲染后为该产品添加专门分支来称泛化成功。未执行的项目保持 `NOT_RUN`。

软件/Skill/技术文档使用 Apache-2.0；品牌库、完整联系人 profile、原件、衍生图、音频和本地报告按各自权利保留在本地。公开软件包不应包含这些私有文件。完整本地备份包括被忽略的品牌资产与全部旧视频。

当前精修：Logo 与主标题左边缘对齐；字幕 30.8px（原 44px 的 70%），正文及标题门槛不变。卡片标题加粗，正文与辅助字段按层级细排，图像沿流程方向揭示，细连线同步推进，卡片位置稳定。屏幕官网文案为“访问恩禾官网，获取更多AI工具和解决方案。”；原口播不改。仅屏幕文案不同的可信规则版本允许复用同一录音；来源与目标仍各自确认，其他规则、声音及时间严格匹配。
