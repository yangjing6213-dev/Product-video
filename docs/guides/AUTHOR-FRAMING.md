# 封面与作者片尾：固定风格，可换人物，每个新任务换场景

本规范适用于新视频任务的封面和关于作者片尾；主片内容与已审核旁白继续按各自方案制作。人物是视觉素材选择，不是配音选择。最新已审核的封面和作者海报是风格基准，历史任务按原冻结画面恢复。

## 1. 风格固定，禁止变更

风格版本为 `enhe-cinematic-glass-v1`。项目内私有文件 `assets/brand/enhe/author/framing-defaults.v1.json` 指向两份已审核基准图及其哈希，不能只靠文字描述重新猜测风格。

- 真实办公/工作空间的摄影质感，深蓝灰与黑色基调、冷暖自然光和克制景深。
- 人物保持基准的自然质感与身份特征；不得擅自变为卡通、动漫、线描、黏土或赛博霓虹风格。
- 原始 ENHE Logo、精致深色半透明玻璃信息区、细边框、少量蓝色强调、清晰白字层级。
- 封面展示中英文项目名称、普通 AI 用户能理解的痛点钩子与简短说明；不增加没有证据的承诺。
- 作者片尾保持已审核的信息层级、完整作者信息和联系方式。文字变更仍走完整文案确认。

可以调整人物动作、取景和真实背景场景。不得以换人物、换项目、换场景为理由变更上述风格。若参考图缺失，先补齐准确本地参考；不得臆造一个“相近风格”当作通过。

## 2. 每个新任务先询问人物

在首次任务输入或集中确认中主动询问一次：

> 这支视频的封面和作者片尾要使用你提供的人物形象吗？可以提供图片；如果没有提供，我会使用项目现有的默认人物。更换人物只影响这两个画面，不会自动改变配音或作者文字。

- 用户已在本次任务提供明确的人物素材，直接使用该输入，不重复询问同一问题。
- 未提供素材或明确选择默认时，使用私有配置中已获授权的现有默认人物。记录 `selection: default` 及实际依据，不把默认使用写成用户上传或新图验收。
- 已发出询问但用户尚未回复时，可按本规范预先授权的默认规则准备候选，记录为 `pending-default-candidate`，不能伪造“用户选择默认”的答复。集中审阅必须明确展示实际采用的人物；只有候选图获实际确认后才能冻结并进入最终合成。期间收到新人素材则更新候选，不得忽略。
- 提供新人时记录 `selection: supplied`，在本地保存原件，核对可读性、来源/使用许可和内容哈希。**同一份人物身份参考同时用于封面和作者片尾**，不能只替换其中一处。
- 上传文件损坏、路径不可读、人物不清楚或多人物无法确定时，报告具体问题；不能悄悄回退默认人物。不要把素材上传理解成新的配音、姓名、联系方式或身份声明授权。
- 保留原件，衍生图另存版本；所有新人物图都要检查脸、手、身体比例和身份一致性。不允许靠文件名或生成完成就判断换人成功。

默认人物不随公开软件分发。全新公开仓库副本若缺少私有默认人物，状态应为 `MISSING_DEFAULT_ASSET`，提示提供人物或安装本人有权使用的本地默认素材；不能使用占位图、网络陌生人照片或空文件冒充默认人物。

## 3. 每支新视频使用不同的背景场景

- 选择与产品用途相符的真实场景，在固定光色与材质风格内变化空间。例如不同的工作室、会议空间或阅读工作区；不增加无关幻想背景。
- 制作前查阅私有场景使用记录 `assets/brand/enhe/author/framing-scene-history.json` 及已有任务的 `framing-plan.json`。同一个新任务使用新的 `sceneId`；不能重用已经用于别的任务的同一空间背景。
- **换颜色、模糊、裁切、镜像、改文件名或仅换机位，不算新场景。** 同时检查场景来源/内容哈希与语义描述；不能只按文件哈希不同判定。
- 同一支视频的封面与作者片尾可以使用同一新场景的不同取景，也可以使用两个新场景；两者都保持固定风格。
- 在并行新任务间先登记场景占用，再生成，避免同一场景被重复选择。无合适未使用场景时准备新的合法素材；涉及额外费用或外部上传仍按原授权边界处理，不降低风格要求。
- **恢复、重渲染和导出不同清晰度不是新任务**：复用原 `sceneId`、图像版本、人物和所有冻结字节。禁止因本规则在断点恢复时随机换背景。

## 4. 记录与制作顺序

1. 读取准确风格参考，询问/解析人物选择，读取场景使用历史并选择未使用的新场景。
2. 在任务内初始化 `framing-plan.json`：`projectId`、`styleVersion`、风格参考路径/哈希、`person.selection`、人物来源路径/哈希与授权依据、封面/片尾各自 `sceneId`/场景描述/来源/哈希。两张候选衍生图实际产出后再追加其真实路径、哈希及审核状态；不得预填假哈希或把计划文件名当作已有资产。路径使用项目相对路径，人物与场景记录仅留本地。
3. 完整确认中英文封面、正文、字幕与片尾文字；制作封面和片尾静态候选，**并排检查同一人物身份及固定风格**，记录实际用户验收。现有风格认可不能自动通过新人或新场景成图的 QA。
4. 冻结已审核的人物、场景与衍生图，使用现有素材快照和文案确认机制进入预览、渲染、媒体 QA。逐帧检查开头封面、主体衔接和片尾，播放前使用封面 poster。
5. 将实际使用场景登记到私有历史，绑定任务与冻结版本。重复执行同一任务不得重复登记或重新选择；变化或损坏的已冻结文件必须明确报错，不静默重新生成替代。

这是 Codex/Skill 的创作执行合同，现有 CLI 不会主动提问、调用人物替换 API，或仅凭本规范自动完成图像编辑。不要把文档/静态契约测试当作真实换人、场景查重或视频成片的验收。运行时仍须检查实际素材、冻结记录与画面。

## 5. QA 与发布边界

分别报告 `PERSON_SELECTION`、`STYLE_MATCH`、`SCENE_DISTINCTNESS`、`COVER_ENDING_IDENTITY`、`FROZEN_RESUME`、`COPY_APPROVAL` 和 `USER_ACCEPTANCE`，使用真实 `PASS / PARTIAL / FAIL / NOT_RUN`。

- 人物选择有记录，默认资产存在或新输入可读且有权使用。
- 封面/片尾人物一致，风格与两份审核基准一致，无脸部漂移、手部缺陷、文字错字或遮挡。
- 新任务场景未与历史重复；同任务恢复保持原人物/场景/衍生图哈希。
- 封面在未播放时完整显示；配音不因视觉换人而变化；作者文字和官网引流保留。
- 软件 Apache-2.0 不覆盖肖像或品牌资产的公开分发。参考原图、人物上传、生成封面/片尾、使用历史、审核记录与视频不进公开 Git/npm/Skill 包。

本规则优先于历史“始终复用整张作者海报”或“默认不放人物”的新任务示例；历史冻结任务仍按其原授权恢复。任何风格改版必须由用户另行明确授权，不能自行升级 `styleVersion`。
